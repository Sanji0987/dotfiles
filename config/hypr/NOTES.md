# Hyprland configuration — `~/.config/hypr`

Hyprland 0.56.1 on CachyOS, using the **Lua config format** (not `hyprland.conf`).
Single monitor `DP-1` (HP OMEN 27 G2, 1920x1080@180Hz, on the RTX 5070 Ti / `card1`;
the Intel Arrow Lake iGPU is `card0`). Desktop PC — no idle, sleep or power saving
anywhere in this setup by design.

The whole look is derived from the wallpaper `~/Pictures/linus.png` (a dusk river
scene: near-black silhouettes, deep slate-blue sky, pale gold sunset on the water).

---

## Layout of this directory

```
~/.config/hypr/
├── NOTES.md           this file
├── hyprland.lua       entry point — only `require` calls, nothing else
├── hyprlock.conf      lock screen (hyprlock, hyprlang syntax, NOT Lua)
├── hyprpaper.conf     wallpaper daemon (hyprlang syntax, NOT Lua)
├── hypridle.conf      idle daemon — lock only, no DPMS/suspend (hyprlang)
├── hyprsunset.conf    colour temperature, fixed 5700K (hyprlang)
└── conf/
    ├── colors.lua       palette table, returned as a module
    ├── omarchy.lua      active Omarchy theme's colours + slug, as a module
    ├── themes/          per-theme look overrides, loaded by theme slug
    ├── programs.lua     default apps + paths, returned as a module
    ├── display.lua      monitor, cursor, misc compositor behaviour
    ├── peripherals.lua  keyboard, mouse, touchpad, gestures
    ├── theme.lua        borders, gaps, opacity, blur, shadows, group bars
    ├── animations.lua   bezier/spring curves and per-leaf animation timings
    ├── layouts.lua      dwindle / master / scrolling layout behaviour
    ├── rules.lua        window, workspace and layer rules
    ├── keybinds.lua     every keybinding
    └── autostart.lua    session env vars + processes started with the session
```

`hyprland.lua.bak` is the original autogenerated single-file config, kept as a fallback.

## How the Lua config works

- Hyprland exposes a global `hl` table. Files are plain Lua, executed at config load.
- `require("conf.display")` resolves to `~/.config/hypr/conf/display.lua` — the config
  directory is on `package.path`, and Lua turns the dot into a directory separator.
- Modules that `return` a table (`colors.lua`, `programs.lua`) are consumed with
  `local c = require("conf.colors")`. Modules that call `hl.*` are required for their
  side effects only.
- Load order is the order of `require` in `hyprland.lua`. Later `hl.config({...})` calls
  merge over earlier ones, so `rules.lua` and `theme.lua` must come before nothing in
  particular — but keep `theme` before `rules` since rules override theme values per window.

### API used here

| Call | Purpose |
|---|---|
| `hl.config({ section = { key = value } })` | set config values; nested tables map to `section:key` |
| `hl.monitor({...})` | monitor declaration |
| `hl.env(name, value)` | session environment variable |
| `hl.bind(keys, dispatcher, opts)` | keybinding; `opts` takes `mouse`, `locked`, `repeating` |
| `hl.dsp.*` | dispatchers — `exec_cmd`, `exit`, `focus`, `layout`, `window.*`, `workspace.*` |
| `hl.window_rule / hl.workspace_rule / hl.layer_rule` | rules, each takes a `name` and a `match` table |
| `hl.curve(name, {...})` / `hl.animation({ leaf = ... })` | animation curves and timings |
| `hl.gesture({...})` | touchpad gestures |
| `hl.on("hyprland.start", fn)` | run a function at session start |

### Gotchas learned the hard way

1. **Unknown keys fail loudly but silently at runtime** — `hyprctl configerrors` is the
   only way to see them. `misc:vfr` and `misc:new_window_takes_over_fullscreen` do *not*
   exist in 0.56.1 and were rejected.
2. **Colors are strings, built by concatenation.** The palette stores bare hex
   (`"060709"`), so the closing paren belongs *inside* the last string:
   `"rgba(" .. c.black .. "b0)"` ✅ — `"rgba(" .. c.black .. "b0")` ✗ (stray paren, Lua
   syntax error).
3. **A bare word is a nil global.** The original config had `accel_profile = flat`,
   which silently evaluated to `nil` and never applied. Quote enum values.
4. After any edit: `hyprctl reload && hyprctl configerrors`. Empty output = clean.

## File-by-file

### `hyprland.lua`
Entry point. Eight `require` lines, no configuration of its own. Add a new area by
creating `conf/<area>.lua` and adding one `require` here.

### `conf/colors.lua`
Returns the palette sampled from `linus.png` with ImageMagick
(`magick linus.png -resize 200x -colors 12 -format %c histogram:info:`). **Bare hex, no
`#`, no `rgba()`** — callers wrap it. Keys, dark → light:

| Key | Hex | Where it came from |
|---|---|---|
| `black` | `060709` | dominant silhouette colour, ~50% of the image |
| `ink` | `141a22` | lifted black for panels |
| `slate` | `2c3748` | the deep blue sky band |
| `deep` / `steel` / `dusk` / `haze` | `394557` / `535c69` / `6b7587` / `7b8493` | sky gradient toward the horizon |
| `pale` | `999fa1` | distant tree line |
| `cyan` | `8fa4ad` | horizon glow |
| `olive` | `969173` | dark reeds |
| `sand` | `d4cba6` | sunset reflection on the water |
| `cream` | `e7e6cf` | brightest point of the sky |
| `red` | `a4696a` | not in the wallpaper; muted addition for alerts only |

This table is now only a **fallback** palette plus the shadow and group-bar colours.
Everything that used to be mirrored out of it follows the active Omarchy theme instead:

| was duplicated into | now |
|---|---|
| window borders | `conf/omarchy.lua`, from the theme's `colors.toml` |
| `hyprlock.conf` | `source`s the theme's own `hyprlock.conf` |
| `~/.config/kitty/current-theme.conf` | generated by `omarchy-kitty-theme-sync` |
| `~/.config/ashell/config.toml` | ashell is gone; the bar is Quickshell |

`~/.config/mako/config` is the one left, and mako is not running either (Omarchy's
shell draws its own notifications). So this table is mostly kept for the shadow
colours and as the last-resort fallback in `conf/omarchy.lua`.

### `conf/omarchy.lua`
Reads the active theme's `colors.toml` from
`~/.local/state/omarchy/current/theme/` and returns it as a table, plus `mix(a, b,
amount)` and `rgba(hex, alpha)` helpers. Used by `theme.lua` for the border colours.

Why it parses the TOML rather than loading the theme's own `hyprland.lua`: six of the
24 installed themes ship one, and it is a `hypr2lua` dump of the entire look —
rounding, blur, opacity, animations, layer rules — so loading it would clobber
`theme.lua` wholesale instead of just recolouring the borders. Themes that ship none
get a *generated* `hyprland.lua` of a different shape again. `colors.toml` is the one
artefact every theme has, and it holds nothing but colours.

It also exposes `M.name`, the active theme's slug, read from
`~/.local/state/omarchy/current/theme.name` and refused unless it matches
`^[%w._-]+$` — it is about to become part of a file path, so the file's contents are
not trusted.

Every lookup falls back (to `conf/colors.lua` values) so a missing or sparse
`colors.toml` cannot error the config at load. No extra wiring is needed to follow a
theme change: `omarchy-theme-set` ends by running `omarchy-restart-hyprctl`, which is
`hyprctl reload`, which re-executes this config.

### `conf/themes/<slug>.lua`
Per-theme look overrides, loaded at the end of `theme.lua` via
`package.searchpath("conf.themes." .. t.name, package.path)` — present means load,
absent means silently skip, and a *broken* one still fails loudly (which is why it
is `dofile` on a resolved path, not `pcall(require, ...)`).

These exist because **Omarchy refuses parts of a theme installed from a git repo**:
every `.lua` file it ships, plus `kitty.conf`, `alacritty.toml`, `ghostty.conf`,
`foot.ini` and `vscode.json` (`omarchy-theme-set:30` and `:142`). Theme Lua would
execute inside the compositor, and a terminal config can name the program the
terminal launches, so the refusal is correct — `omarchy-theme-set` prints exactly
what it ignored. Where such a theme's look depends on those files, the values get
read, reviewed and written here instead.

Loading the theme's own `hyprland.lua` would be wrong even if it were allowed: it is
a `hypr2lua` dump of the entire look, animations and layer rules included, so it
would replace `theme.lua` rather than merge over it.

`rainynight.lua` is the worked example — rounding 14, a *bright* blur (contrast and
brightness above 1, where the base look darkens to 0.72), 0.93/0.92 opacity,
`dim_inactive = false` because the theme carries focus with opacity alone, and the
theme's own indigo borders. It deliberately does **not** touch gaps or animations,
which are hand-tuned in the base look.

### `conf/programs.lua`
Returns default applications and paths so `keybinds.lua` and `autostart.lua` agree:
`terminal = kitty`, `fileManager = dolphin`, `menu = hyprlauncher`, `lock = hyprlock`,
`wallpaper` (absolute path via `os.getenv("HOME")`), `shotDir` (`$HOME/...`, left
unexpanded because it is used inside a shell command string).

### `conf/display.lua`
- `hl.monitor` — DP-1, `1920x1080@179.98`, position `0x0`, scale 1.
- Cursor size 20 for both XCursor and hyprcursor.
- `cursor:inactive_timeout = 0` and `hide_on_key_press = false` — the pointer never
  auto-hides. Deliberate: this is a desktop, nothing should time out.
- `misc` — mascot wallpaper and splash off (hyprpaper owns the background),
  `focus_on_activate` on.

### `conf/peripherals.lua`
- `accel_profile = "flat"` with `sensitivity = 0` — raw 1:1 mouse input, no acceleration.
- `repeat_rate 35` / `repeat_delay 200`, numlock on at login, `follow_mouse = 1`.
- Touchpad block (natural scroll, tap to click, disable while typing) is harmless on a
  desktop and there for when a touchpad is attached.
- Three-finger horizontal swipe switches workspaces.
- Per-device overrides would go here as `hl.device({ name = "...", sensitivity = ... })`.

### `conf/theme.lua`
The look. Requires `conf.colors` as `c` and `conf.omarchy` as `t`.

- **Borders: 2px, theme-derived.** The active border is a 45° gradient from the
  theme's `accent` to that same accent mixed 62% into the theme background — a sheen
  rather than a second hue, which is what keeps it working on the monochrome themes
  (`vantablack`, `white`, `matte-black`) where any contrasting colour would clash.
  The inactive border is flat: the background lifted 14% toward the foreground, so
  it reads as an edge without competing for attention.
  This replaced an earlier 1px pure-black-on-both-states design, where focus was
  carried entirely by `inactive_opacity` + `dim_inactive` + the shadow. Those are all
  still in place; the border now reinforces them instead of being invisible.
- **Gaps: `gaps_in = 4`, `gaps_out = 8`.** `gaps_in` is applied to each side, so
  two adjacent windows show 8px between them, matching the 8px to the screen
  edge — one spacing everywhere rather than a thinner seam in the middle.
- `rounding = 0` — square by choice. The original reason was that rounded corners
  at 1px borders and 1px gaps exposed wedges of wallpaper between windows; at the
  current 2px/2px it is a closer call again, but it stays taste, not a constraint.
- `resize_on_border` + `extend_border_grab_area = 12` — makes a thin border grabbable.
- Shadows use the wallpaper's own near-black (`c.black` at `b0` / `60` alpha).
- Blur: 6/3 passes, `ignore_opacity`, brightness `0.72`, slight noise and vibrancy —
  tuned so translucent surfaces stay in the wallpaper's dusk mood rather than glowing.
- Group bars (tabbed groups) take the same themed border as ordinary windows; the
  bar itself still uses `slate` for the active tab and `red` for a locked group.

### `conf/animations.lua`
Hyprland's default curve set (`easeOutQuint`, `easeInOutCubic`, `linear`,
`almostLinear`, `quick`, plus the `easy` spring) and per-leaf timings. Fast and
understated — window open/close uses the spring with `popin 87%`, workspaces cross-fade.
Nothing here is wallpaper-specific; safe to retune freely.

### `conf/layouts.lua`
`dwindle` is the active layout (set in `theme.lua` via `general:layout`).
`preserve_split` and `smart_resizing` on, `force_split = 2` so new windows always open
to the right/below rather than following the cursor. `master` and `scrolling` blocks are
configured but unused unless the layout is switched.

### `conf/rules.lua`
Reads top to bottom: window rules, then workspace rules, then layer rules.

- `suppress-maximize-events` — ignores maximize requests from every app.
- `fix-xwayland-drags` — the standard empty-class/empty-title XWayland drag fix.
- `float-dialogs` — file pickers float, 900x600, centred.
- `games-raw` — matches `steam_app_*`, `cs2`, `gamescope`, `hl2_linux`, `*.exe` and
  disables blur, dim, shadow and animations. Keeps the compositor out of the way in games.
- `pip-on-top` — Picture-in-Picture floats and pins.
- `move-hyprland-run` — carried over from the original config.
- **Smart gaps**: `f[1]` (single fullscreen) gets `gaps_in/out = 0` and the matching
  window rule drops `border_size` to 0, so fullscreen really is edge-to-edge.
  `w[tv1]` (single tiled window) used to do the same and no longer does — losing
  the gaps *and* the border on the commonest layout of all undid both of them.
- **Layer rules** blur the `ashell` bar, `notifications` (mako) and `hyprlauncher` so the
  wallpaper reads through them; `selection` (slurp) gets no animation.

### `conf/keybinds.lua`
`mainMod = SUPER`. Requires `conf.programs`.

| Bind | Action |
|---|---|
| `SUPER + Return` | kitty |
| `SUPER + E` | dolphin |
| `SUPER + Space` | hyprlauncher |
| `SUPER + W` | close window |
| `SUPER + F` | toggle float |
| `SUPER + P` | pseudo |
| `SUPER + J` | toggle split |
| `SUPER + Shift + M` | exit Hyprland |
| **`SUPER + Shift + L`** | **lock (hyprlock)** — guarded by `pidof` so it cannot stack |
| `SUPER + Shift + P` | region screenshot → clipboard + `~/Pictures/Screenshots` |
| `Print` | full screenshot → clipboard + `~/Pictures/Screenshots` |
| `SUPER + V` | clipboard history (`cliphist` piped through `hyprlauncher --dmenu`) |
| `SUPER + ←↑↓→` | move focus |
| `SUPER + 1..0` | workspaces 1–10 (10 is on key `0`) |
| `SUPER + Shift + 1..0` | move window to workspace |
| `SUPER + S` / `SUPER + Shift + S` | special workspace `magic` — toggle / move to |
| `SUPER + scroll` | cycle workspaces |
| `SUPER + LMB / RMB` | drag / resize window |
| XF86 volume / media keys | `wpctl` and `playerctl`, `locked = true, repeating = true` |
| XF86MonBrightness Up/Down | `ddcutil --noverify setvcp 10 ± 5`, `locked = true`, **not** repeating |

Brightness goes over **DDC/CI**, not `/sys/class/backlight` — this is a desktop and
there is no backlight device, so `brightnessctl` silently did nothing. `ddcutil`
reaches the OMEN 27 G2 on `/dev/i2c-4` (`ddcutil detect` to confirm; the `i2c-dev`
module is loaded and the user's group membership already allows access). Each call is
a ~1s i2c round trip, which is why `repeating` is deliberately off — key repeat would
queue dozens of writes.

Locking is **manual only**. There is no idle timer: `hypridle` is installed but is not
started by `autostart.lua` and has no config file, and no idle/sleep systemd user units
are enabled. Do not add one without being asked.

Note when editing: `--dmenu` inside a command string is a CLI flag, not a Lua comment.
A careless comment-stripping regex will eat it and break the `SUPER + V` bind.

### `conf/autostart.lua`
Environment variables (`XDG_CURRENT_DESKTOP=Hyprland`, `QT_QPA_PLATFORMTHEME=kde`,
Qt decoration off, Electron Ozone auto, Firefox Wayland) then `hl.on("hyprland.start")`:

| Process | Role |
|---|---|
| `ashell` | status bar |
| `mako` | notification daemon |
| `hyprpaper` | wallpaper |
| `hyprsunset` | colour temperature, reads `hyprsunset.conf` |
| `hypridle` | idle → lock only, reads `hypridle.conf` |
| `wl-paste --watch cliphist store` | clipboard history recorder |
| `wl-clip-persist --clipboard regular` | keeps clipboard contents after the source app exits |
| `dex -a` | XDG autostart entries |
| `/usr/lib/polkit-kde-authentication-agent-1` | polkit auth prompts |

The polkit path ends in **`-1` (one)**, not `-l` (letter L). The original config had the
letter and no auth agent ever started.

### `hyprlock.conf`
hyprlang syntax, not Lua. **No colours of its own**: it `source`s the active theme's
`hyprlock.conf` from `~/.local/state/omarchy/current/theme/`, which supplies
`$color`, `$inner_color`, `$outer_color`, `$font_color`, `$placeholder_color` and
`$check_color`. The background is the theme's wallpaper through the
`current/background` symlink, blurred 3 passes at 0.55 brightness. So the lock
screen follows a theme change with no edit.

Layout, rebuilt from the rainynight theme's screenshots: hour over minute at 190pt
in `JetBrainsMono NF ExtraBold`, a 230x2 `shape` rule, weekday and `%d %b`, the
current track, a lock glyph, a pill input field (`rounding = -1`) and `$USER` in
italics. `hide_cursor` and `ignore_empty_input` on.

Two traps:
- Pango markup needs `##` to escape a literal `#`.
- **hyprlang reads `{{ }}` as an arithmetic expression**, so `playerctl --format
  '{{title}}'` fails to parse with *"Invalid expression type: supported +, -, *, /"*.
  Hence `playerctl metadata title`, which needs no braces.

There is no `--dry-run`, but `hyprlock --display <bogus>` parses the config and
reports its errors before asserting on the missing compositor — that is the offline
syntax check, and it beats locking yourself out to find a typo.

### `hyprpaper.conf`
hyprlang syntax. One `wallpaper { }` block: `monitor = DP-1`, `path = ~/Pictures/linus.png`,
`fit_mode = cover`. Verify with `hyprctl hyprpaper listactive`.

**Dead weight.** hyprpaper is not running, and the wallpaper is drawn by Quickshell
instead (the `omarchy-background` layer, visible in `hyprctl layers`) from the
`current/background` symlink. This file also still names `DP-1`, which no longer
exists — the monitor is `DP-2`. Left in place rather than deleted, but nothing reads
it.

### `hypridle.conf`
hyprlang syntax. Deliberately minimal: **one** listener, 900s → `loginctl lock-session`.
hypridle binds `hyprland_lock_notifier_v1` and handles the logind Lock signal itself,
so `loginctl lock-session` routes back to `general:lock_cmd`
(`pidof hyprlock || hyprlock`) — the same guarded invocation as `SUPER + Shift + L`.
That single path means the keybind, ashell's lock button and the idle timeout can
never end up with three different lock behaviours.

There is intentionally **no** DPMS listener, no `brightnessctl` dimming and no
`systemctl suspend`, and **no** `before_sleep_cmd`/`after_sleep_cmd` — this is a
desktop and the standing instruction is no power management. Only add those back if
explicitly asked. hypridle still takes a logind sleep inhibitor on startup
(`Inhibited sleep with fd N` in its log); that is a side effect of it registering as
a sleep handler and it makes the machine *less* likely to suspend, not more.

ashell's `IdleInhibitor` indicator (in `[settings] indicators`) speaks
`zwp_idle_inhibit_manager_v1` and will suppress the 900s timeout while toggled on.

### `hyprsunset.conf`
hyprlang syntax. `max-gamma = 150` plus a single `profile { }` at `time = 00:00`,
so 5700K is applied all day rather than on a day/night schedule — slightly warmer
than the 6500K sRGB white point without an orange cast.

**Gotcha:** `gamma` inside a profile is a *multiplier*, not a percentage.
`gamma = 100` is parsed as 10000% and hyprsunset refuses to start with
`Gamma invalid: 10000%`. Use `gamma = 1.0` for neutral. The CLI flag `--gamma`
takes a percentage, which is where the confusion comes from.

Runtime control without editing the file:
`hyprctl hyprsunset temperature` reads it, `hyprctl hyprsunset temperature 6500`
sets it, `hyprctl hyprsunset identity` disables the shift entirely.

### ashell integration notes

`region = "en_GB"` forces **metric units (°C, km/h)** and UK date format, because the
system locale is `en_US.UTF-8` and ashell otherwise derives Fahrenheit from
`LC_MEASUREMENT`.

`[settings]` helper commands must be things that actually run **outside a Plasma
session**. The original config used Plasma pieces that don't work here:

| Key | Was | Now | Why |
|---|---|---|---|
| `lock_cmd` | `playerctl --all-players pause; hyprlock &` | `pidof hyprlock || hyprlock` | the `playerctl` half was left over from the deleted music module; the new form is the same guarded command as `SUPER + Shift + L`, so it can't spawn a second hyprlock |
| `audio_sinks_more_cmd` | `kcmshell6 kcm_pulseaudio` | `pavucontrol -t 3` | both sink/source buttons opened the same default tab; `-t` is 1-indexed, 3 = Output Devices, 4 = Input Devices |
| the app-launcher `CustomModule` | `krunner` | `hyprlauncher` | krunner needs Plasma's session D-Bus services and silently does nothing under Hyprland |

`wifi_more_cmd` / `vpn_more_cmd` (`nm-connection-editor`) and `bluetooth_more_cmd`
(`kcmshell6 kcm_bluetooth`) were unset, so those buttons never appeared. Both binaries
were verified to launch standalone — unlike krunner, `kcmshell6` KCMs are plain Qt apps.

`shutdown_cmd = "shutdown now"` is correct and left alone: systemd's `shutdown`
defaults to `--poweroff`, it does not halt or drop to rescue.

**Known benign noise:** ashell logs `No backlight devices found` /
`Brightness service error` on every start. `src/app.rs` always subscribes to the
brightness service ("so OSD works") regardless of the `indicators` list, and this
desktop has no backlight device. Not fixable from config; ignore it.

`.bak` files sit next to the originals for `hyprland.lua`, `kitty/current-theme.conf`
and `ashell/config.toml`.

## Verifying changes

```sh
hyprctl reload && hyprctl configerrors     # empty output = clean
hyprctl getoption general:border_size      # check a specific value took effect
hyprctl binds -j | jq length               # binds registered (52 currently)
makoctl reload                             # after editing mako config
hyprctl hyprsunset temperature             # should print 5700
pkill hypridle; hypridle                   # hypridle has no reload; restart to apply
pkill -x ashell && setsid ashell &         # after editing ashell config
```

ashell logs to `/run/user/1000/ashell_rCURRENT.log`. Its
`No backlight devices found` errors are expected on a desktop and can be ignored.

Kitty colour changes only apply to newly opened windows.
